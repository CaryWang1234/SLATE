1 SLATE 是什么？What is SLATE?

SLATE（砚）是一款本地优先的 AI 协作调度台。它把主流大模型、34 个内置工具、团队辩论、DAG 工作流、白板式逻辑链整合在一个轻量界面里——零 npm、零构建、开箱即用。

核心理念：让灵感直达行动，中间不隔工具摩擦。

SLATE is a local-first AI collaboration studio. It integrates mainstream LLMs, 34 built-in tools, team debates, DAG workflows, and whiteboard logic chains — all in a lightweight interface. Zero npm, zero build, ready to use.

Core philosophy: Let ideas go straight to action, without tool friction in between.

3 多模型对话Multi-Model Chat

SLATE 支持同时接入多个模型，在对话界面顶部下拉框随时切换。

  • 点击模型下拉框 → 添加/切换模型
  • 不同对话可使用不同模型
  • 支持本地模型（Ollama / LM Studio 的 OpenAI 兼容端点）
  • 每条回复显示模型名称与 Token 用量
快捷键：Enter 发送 · Shift+Enter 换行 · Ctrl+N 新建对话
＋ 模式菜单：输入框左侧的 ＋ 按钮集中了模式入口 —— 磨墨 / 头脑风暴 / 目标模式 / 定时任务，以及「提及」分组（技能 / 工具 / MCP / 文件），点击行即可启动对应模式或弹出对应候选列表。

SLATE supports multiple models simultaneously — switch anytime from the top dropdown.

  • Click model dropdown → Add/switch models
  • Different conversations can use different models
  • Supports local models (Ollama / LM Studio via OpenAI-compatible endpoints)
  • Each reply shows model name and token usage
Shortcuts: Enter to send · Shift+Enter for newline · Ctrl+N for new conversation
＋ Mode Menu: The ＋ button left of the chat input centralizes mode entries — Grind / Brainstorm / Target Mode / Scheduled Tasks — plus an @-mention group (Skills / Tools / MCP / Files) that opens a filtered picker.
4 Agent Autopilot + 目标模式自主执行Agent Autopilot + Target Mode

Agent Autopilot 是默认的”少打继续”执行层。只要你要求 SLATE 查看项目、修改文件、运行命令、排查 bug、提交代码或生成文件，它会自动进入多轮 Agent Loop，不需要反复发送”继续”。

默认轮数：普通环境任务最多 18 轮；全面排查、项目级、多文件任务最多 28 轮。系统会把工具结果隐藏回灌给模型，让它继续观察 → 执行 → 验证 → 汇报。

如果模型只说”我将检查 / 接下来修改 / 是否继续”，系统会自动催它直接调工具；如果没有任何工具记录却口头说完成，系统会要求它先验证或真正动手。

砚流 · 落笔即所见：模型正在逐个 token 写工具参数时，SLATE 会按本地工具 schema 解析这份还没写完的参数，实时演成一行预览——哪些字段已经闭合、哪个字段正在写。它只做预览，半成品参数永不触发执行；几十 KB 的正文类字段一律折叠成行数与字数，不刷屏。

停止是真取消：点击停止会同时关闭模型流与工具调用的流式通道，后端随即终止对应的子进程与在跑任务，不再是“界面停了、活还在干”。被取消的调用会以独立状态记进本地事件账，与正常完成区分开。

目标模式 是更强的显式闭环模式。需要 50 轮长任务、明确 TODOLIST 和六阶段约束时，点击输入框左侧 ＋ 菜单里的「目标模式」开关，或在消息中提及「用目标模式执行」。

六阶段流程：

  1. 目标理解 → 解析你的需求
  2. 计划制定 → 拆解为可执行步骤
  3. 工具执行 → 自主调用文件/终端/搜索等工具
  4. 验证检查 → 确认每步结果
  5. 汇报总结 → 输出执行报告
  6. 追溯归档 → 记录到 TODOLIST
特性：最多 50 轮自主调用 · 中途可暂停不丢进度 · 自动建立 TODOLIST · 异常自动恢复

Agent Autopilot is the default "do not make me type continue" execution layer. When you ask SLATE to inspect a project, edit files, run commands, debug, commit, or generate files, it automatically enters a multi-round Agent Loop.

Default budgets: ordinary environment tasks can auto-advance up to 18 rounds; broad project-wide or multi-file tasks can auto-advance up to 28 rounds. Tool results are fed back invisibly so the model can continue Observe → Act → Verify → Report.

If the model only says it will inspect/edit/continue, SLATE nudges it to call tools. If it claims completion without any tool evidence, SLATE asks it to verify or actually act first.

InkStream — arguments as they are written: while the model streams a tool call token by token, SLATE parses the half-formed arguments against the local tool schema and shows a live one-line preview of which fields are already closed and which one is still being written. It is preview only — incomplete arguments never reach execution; multi-KB text fields fold into line and character counts instead of flooding the screen.

Stop really cancels: pressing Stop closes both the model stream and the tool-call stream, so the backend terminates the matching subprocess or running task instead of "UI stopped, work still going". Cancelled calls are recorded in the local event ledger under their own status, kept apart from successful ones.

Target Mode is the stronger explicit loop. Toggle "Target Mode" in the ＋ menu (left of the chat input), or mention "use Target Mode", when you want 50 rounds, TODOLIST enforcement, and six-phase constraints.

Six-Phase Flow:

  1. Goal Understanding → Parse requirements
  2. Plan Creation → Break into steps
  3. Tool Execution → Autonomously call tools
  4. Verification → Confirm each result
  5. Report → Output summary
  6. Trace → Log to TODOLIST
Features: Up to 50 rounds · Pause anytime · Auto TODOLIST · Auto-recovery

5 磨墨模式Grind Mode

把粗糙想法研磨成结构化任务书（墨稿）的交互式引导。

启动：输入 /grind 你的想法，或点击输入框左侧 ＋ 菜单里的「磨墨模式」。输入抽象任务（如"制作一个网站"）时自动建议切换。

阶段说明
接墨AI 复述想法，列出 3-5 个缺口，只问第一个
磨墨逐轮追问，一次一问，选择题优先（最多 10 轮）
收墨输出结构化 JSON 墨稿，含目标/交付物/验收标准

收墨触发：输入「收墨」「够了」「就这样」或达到轮数上限

墨稿三键：送入目标模式执行 / 投到白板推演 / 存为模板复用

Interactive refinement: turn rough ideas into structured task briefs.

Launch: Type /grind your idea, or open the ＋ menu (left of the chat input) → Grind Mode. Auto-suggests when detecting abstract tasks.

PhaseDescription
ReceiveAI restates idea, lists 3-5 gaps, asks only the first
GrindRound-by-round, one question at a time, A/B choices preferred (up to 10 rounds)
CollectOutputs structured JSON brief with goals/deliverables/acceptance

Trigger Collect: Type "收墨" / "够了" / "就这样" or reach round limit

Three Actions: Send to Target Mode / Push to Whiteboard / Save as Template

6 团队模式Team Mode

多个 AI 角色围绕你的问题进行多轮辩论，最终输出共识结论。

  1. 点击顶栏「团队」标签
  2. 选择团队成员（9 种预设组合或自定义）
  3. 输入问题 → 各成员按角色依次发表观点（3 轮辩论）
  4. 输出共识总结

自定义团队：设置 → 团队管理 → 添加/编辑成员，每个成员可指定模型、角色、人设。

Multiple AI roles debate your question across rounds, producing a consensus conclusion.

  1. Click "Team" tab
  2. Select members (9 presets or custom)
  3. Enter question → Members speak in role order (3 rounds)
  4. Consensus summary output

Custom Teams: Settings → Team Management → Add/Edit members with model, role, persona.

特殊字符与编码：file_peek / file_edit 自动识别 UTF-8、UTF-8 BOM、GB18030、GBK、UTF-16 等常见文本编码；中文、emoji、全角符号会原样保留。Windows 下 terminal 隐藏 PowerShell 子窗口，并对 Python / Node / Git / npm / rg 等原生命令做 Unicode-safe 输出捕获。

Actions 流程说明书：除了内置工具，你还可以把「干某件事的必要流程」写成一份 data/actions/<id>.yml，让模型按你的流程办事。一份 Action 描述「这件事怎么做」，SKILL.md 描述「怎么装一个外部工具」，两者定位不同、互不覆盖。

  • 字段：name · description · when · tags · author · inputs · steps · output，steps[].tool 只是建议，模型可按实际情况换用工具
  • 模型侧只注入目录（最多 20 条，只给 id + 名字 + 一句话），要完整流程需用 actions_read 取；目录列表用 actions_list
  • 「读到流程」不等于「做过流程」：结果摘要与流程单都会提醒模型按步骤实际执行，不要凭说明书编造结论
  • YAML 子集校验（SAY-1）会拒收 Tab 缩进、锚点、多文档、流式 {} / []、折叠块 >、!! 标签，并报出所在行号；改坏的 yml 在面板里仍然可见并显示原因，不会凭空消失
  • 编辑入口：设置 → 技能与工具 → Actions 区块，点「＋ 新建 Action」或点条目进编辑器；边写边校验，报错按行号显示，校验不过保存按钮不会写盘
  • 每次覆盖或删除都会先把原文留底到 data/actions/.history/（每份最多 5 版），编辑器里的「历史版本」可查看某一版原文或直接回滚
  • 模型可代写：actions_write 要求 yml 里声明 author: model（面板据此显示「模型代写」徽标），「询问」权限模式下会弹出原文让你审批；「自动 / 越权」不弹窗，但格式校验始终生效
  • 聊天框 @<id> 提及可把整份流程注入这条消息，注入上限 6000 字，超出部分会提示模型用 actions_read 读全文

Unicode and encoding: file_peek / file_edit auto-detect UTF-8, UTF-8 BOM, GB18030, GBK, UTF-16, and other common text encodings. Chinese, emoji, and full-width symbols are preserved as-is. On Windows, terminal hides PowerShell windows and captures Unicode-safe output for native commands such as Python / Node / Git / npm / rg.

Action Playbooks: beyond the built-in tools, you can write the required procedure for a task as a data/actions/<id>.yml file and have the model follow it. An Action describes "how this task is done"; a SKILL.md describes "how to install an external tool". The two have different roles and never overwrite each other.

  • Fields: name · description · when · tags · author · inputs · steps · output. steps[].tool is advisory — the model may pick a different tool when the situation calls for it
  • Only the catalog is injected into the prompt (up to 20 entries: id, name, one-line summary). Use actions_read for the full procedure and actions_list for the catalog
  • Reading a playbook is not the same as following it: both the tool summary and the rendered procedure remind the model to actually execute the steps instead of inventing results
  • The YAML subset validator (SAY-1) rejects Tab indentation, anchors, multi-document files, flow {} / [], folded > blocks and !! tags, and reports the offending line number. Broken files stay visible in the panel with their reason instead of disappearing
  • Where to edit: Settings → Skills & Tools → the Actions section. "+ New Action" or clicking an entry opens the editor; validation runs as you type with line numbers, and Save refuses a failing draft
  • Every overwrite or delete first copies the previous text to data/actions/.history/ (up to 5 versions per Action). The editor's "History" button shows any version or rolls back to it
  • The model can author one too: actions_write requires author: model inside the yml (the panel badges it "Model-written"), and in "Ask" permission mode the exact content is shown for approval first. "Auto" / "Full access" skip the dialog, but the format gate always applies
  • Typing @<id> in the chat box injects the whole flow into that message, capped at 6000 characters; the trimmed remainder is flagged so the model reads the rest with actions_read

设计原则：

  • 纯粹黑白灰底色 — 不做蓝紫渐变、不滥用圆角、不靠阴影和毛玻璃，金色只做点缀。
  • 本地优先 — 数据全在本地；API Key 只用于调用大模型，聊天、记忆、文件不经过任何第三方服务器。
  • Token 经济 — 智能压缩、分级调用、静默处理，历史对话折成摘要，省额度也不丢要点。
  • 永不冻结 — 四层超时防御覆盖流式与工具调用，慢可以等，卡死不行。
术语提示：Token 是大模型计费与记忆窗口的「字数单位」——上下文越长，花费越高、越容易遗忘。

Design principles:

  • Pure black-white-gray base — no blue-purple gradients, no excess rounding, no shadow or frosted glass; gold is only an accent.
  • Local-first — data stays local; API keys are used only to call models, and chats, memories and files never pass through a third-party server.
  • Token economy — smart compression, tiered calls, silent processing: old conversation folds into summaries, saving budget without losing the point.
  • Never frozen — four layers of timeout defense covering streaming and tool calls. Slow is waitable; stuck is not.
A term worth pinning down: tokens are the unit an LLM bills and remembers by — the longer the context, the more it costs and the more it forgets.
