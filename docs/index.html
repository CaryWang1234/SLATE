Differences

Four Things a Hosted Agent Can't Easily Be

Not a feature race — every one of these follows from who owns the runtime. Each one is also checkable in this repository, so treat the claims below as code review, not copy.

01

Your keys never pass through us — because there is no us.

SLATE holds no master credential and routes nothing through a vendor cloud. You paste each provider's key once, into a local file; it goes from your machine straight to the endpoint you chose, per request.

Typical hosted agent

Usage is metered in credits the vendor sets. Prompts, code and files are indexed on their infrastructure, and the model list is whatever they enabled this month.

SLATE

Bring your own key and your own hardware. Switch provider mid-task, cheap models for drafting and a heavy one for the final call, or run a local model that never leaves the room. Nothing is locked; nobody bills you for switching.

# backend/routers/proxy.py
_stream_openai / _stream_responses
_stream_anthropic / _stream_google
# the key arrives with each request
# no server-side vault, no account,
# no login screen in this codebase

Evidence: backend/routers/proxy.py backend/routers/settings.py frontend/js/store.js

02

Every step is a row you can read afterwards.

One loop kernel emits ordered events, and each plan, start, finish and cancel is written to a local ledger. What you see on screen is not a re-rendered console log — it is a projection of stored records.

Typical hosted agent

A spinner, then a final diff. When round fourteen goes the wrong way, the reasoning and the half-finished calls that led there are not retrievable by you.

SLATE

Sequence-checked events on disk, so a retry can't double-count a call. Same source feeds the tool cards, the whiteboard step cards and the per-session usage summary — one truth, three views.

-- data/chat_history.db
runs        (run_id, …)
tool_events (run_id, seq, kind, …)
  UNIQUE(run_id, seq)  -- INSERT OR IGNORE
call.start → call.finish | call.cancel
digests capped at 2000 chars per event

Evidence: frontend/js/services/agent_loop.js frontend/js/services/agent_ledger.js backend/routers/events.py

03

Stop means stop — and a stuck loop notices itself.

Cancelling closes both the model stream and the tool stream; for streaming tools the backend reads a closed stream as the cancellation signal and terminates the running child process. Around it, four layers make sure "slow" never becomes "frozen".

Typical hosted agent

"Stop" halts the interface while the job carries on somewhere else — and keeps spending. A loop that spins on the same failing call needs a human to notice.

SLATE

90-second stream-idle watchdog, zero-output backoff and retry, 180-second request and tool timeouts, UI watchdog for forced recovery. Identical calls deduplicate: two rounds warn, four rounds exit with a stated reason. Half-written tool arguments are previewed but never executed.

// frontend/js/services/api.js
STREAM_IDLE_TIMEOUT_MS = 90000
STREAM_MAX_RETRIES     = 2
REQUEST_TIMEOUT_MS     = 180000
// chat.js — stall guard
WARN_ROUNDS = 2 · EXIT_ROUNDS = 4
// skills.py — closed stream == cancelled

Evidence: backend/routers/skills.py frontend/js/services/inkstream.js frontend/js/components/chat.js

04

Adding a capability is a file drop, not a release.

Thirty-four tools ship ready. Beyond them, one SKILL.md directory in your local skills folder is live on next message — @mention it and its context injects itself.

Typical hosted agent

The capability set is whatever the vendor shipped last. Extending it means waiting on a roadmap you don't control, or a plugin API they may deprecate.

SLATE

Skill folders drop in and take effect. An MCP client attaches external servers; SLATE also serves MCP itself, so other agents can call it. Existing skill directories from other agent ecosystems import as-is.

# data/skills/my-skill/SKILL.md
---
name: my-skill
description: what it teaches SLATE
---
# external tools appear as:
mcp__{serverId}__{toolName}

Evidence: backend/routers/skills.py backend/mcp_client.py backend/routers/mcp.py backend/skills/plugin_adapter.py

Capabilities

What Those Four Differences Buy You

The inventory is long and deliberately not here. These five are what a local, auditable, bring-your-own-key runtime makes possible in practice.

📦

Deliverables, Not Just Text

Runs end in files you can send: .pptx, .docx, .xlsx, extracted PDF text and tables, SVG charts, QR codes, portable single-file web bundles. Editing preserves UTF-8 / BOM / GB18030 and handles Chinese and emoji without corrupting them.

🧠

Memory That Stays on Your Disk

Chat history in local SQLite, a local vector knowledge base, an Obsidian-style vault with [[wiki-link]] backlinks, and long-term memory that auto-distills across sessions. None of it is uploaded to be "improved".

📡

Reach Beyond the Desk

Turn on LAN access and your phone gets a dedicated mobile UI — same chat, same tool loop, bottom-sheet confirmation for high-risk commands. Browser and desktop automation, plus scheduled and event-driven tasks (file change, git push, webhook).

👥

More Than One Brain

Several models debate: propose, support, oppose, decide, with light models doing the talking and a heavy one making the call. A DAG pipeline runs requirements → decompose → code → review → summarize, and parallel subagents fan out when a task splits.

🔍

Read the Source, Skip the Build

Vanilla ES modules, no npm, no bundler — edit a file, refresh, it works. The whole frontend is the product, and every claim on this page has a path you can open.

Want the full list? Chapter 17 of the guide carries every capability with a one-line description, all 34 tools, the use cases and the tech stack; the rest of the guide covers each panel, the 8 workflow templates and the settings walkthrough — in Chinese and English.

Honest Limits

The Same Ownership Costs You Something

A comparison page that lists only wins is a brochure. Local, single-user, bring-your-own-key is a trade — here is what SLATE gives up to have it.

No Hosted Workspace

No organisations, no shared review, no server API. It is one person's desktop, and team features would change what it is.

Guardrails, Not a Jail

The terminal tool runs a real shell. Twenty-three categories of high-risk commands ask for confirmation first and catastrophic ones are blocked outright — but a denylist is a rail, not a sandbox.

Keys in a Local File

Model keys sit in plaintext JSON inside your data directory, not in the OS keychain. Anything that can read that folder can read them.

Not Offline

Three CDN scripts (highlight.js, Mermaid, anime.js) load on start. Air-gapped use means mirroring them yourself first.

Windows & macOS First

Installers ship for Windows (WebView2 required) and disk images for macOS. Linux runs from source, with no packaged build.

LAN Is the Whole App

If you turn on remote control, that network can drive everything — terminal included — behind one token and an optional password. Off unless you enable it.

Quick Start

Three Steps, Then Judge for Yourself

Step one is all a non-coder needs. Steps two and three are for anyone who intends to read the loop before trusting it.

01

Install or Clone

A per-user Windows installer from Releases — no administrator rights, clean uninstall. Or read the source:

git clone https://github.com/CaryWang1234/SLATE.git
02

Launch

From source you need Python 3.13+. Two commands start the local service:

pip install -r requirements.txt
start.bat  # or ./start.sh
03

Paste One Key

Add the key for any model you already have — or point it at a local Ollama / LM Studio endpoint and add none. Then open:

http://127.0.0.1:8000

Nothing to sign up for, nothing to migrate. Your history, memory, skills and usage data are files on your own disk from the first run.

Run it against the agent you already pay for.

Install SLATE, point it at a key you already hold, and give both the same task. The loop, the ledger and the limits are all in the open — MIT licensed, and yours to audit.
